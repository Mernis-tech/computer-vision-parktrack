# Минимальная конфигурация сервера

## 1. Что запускается

В локальной сборке ParkTrack есть пять постоянно работающих компонентов:

- PostgreSQL;
- MinIO;
- FastAPI;
- админ-панель на Nginx;
- сервис компьютерного зрения.

Миграции, инициализация MinIO и создание демонстрационных данных запускаются однократно. Текущий детектор работает на CPU, обрабатывает три кадра размером 640 пикселей и по умолчанию использует один рабочий процесс.

## 2. Нижняя граница для демонстрации

Подходит для одной камеры, обработки раз в 2–5 минут и небольшой истории.

| Ресурс | Минимум |
|---|---:|
| CPU | 2 современных ядра x86-64 |
| Оперативная память | 4 ГБ |
| Диск | 25 ГБ SSD |
| GPU | не требуется |
| Сеть | 20 Мбит/с, стабильный исходящий доступ к камере |
| ОС | Ubuntu Server 22.04/24.04 или Windows 11 с WSL 2 |

Это технический минимум. Во время сборки Docker-образов, параллельной работы интерфейса и инференса возможны задержки или использование файла подкачки.

## 3. Рекомендуемый минимальный сервер

Подходит для разработки, демонстрации и 1–4 камер при периодической обработке.

| Ресурс | Рекомендация |
|---|---:|
| CPU | 4 физических/виртуальных ядра с AVX2 |
| Оперативная память | 8 ГБ |
| Диск | 50 ГБ SSD/NVMe |
| GPU | не требуется |
| Сеть | 100 Мбит/с |
| ОС | Ubuntu Server 24.04 LTS |

Для учебного развёртывания команды именно эту конфигурацию стоит указывать как минимально комфортную: **4 vCPU, 8 ГБ RAM, 50 ГБ SSD, без обязательной видеокарты**.

## 4. Когда нужна видеокарта

GPU становится полезен, если требуется обрабатывать много камер, уменьшить интервал до нескольких секунд или анализировать видео почти в реальном времени. Текущий скрипт ParkTrack принудительно использует `CPU`, поэтому одной установки видеокарты недостаточно: нужно разрешить устройство `GPU` или `AUTO` и передать его в контейнер.

Ориентир для ускоренного варианта:

- 8 vCPU;
- 16 ГБ RAM;
- NVIDIA GPU с 6–8 ГБ видеопамяти либо совместимый ускоритель OpenVINO;
- 100 ГБ NVMe.

Точную конфигурацию выбирают только после замера времени одного цикла на реальных камерах.

## 5. Расчёт диска для снимков

Модели занимают мало места: наша `best.pt` около 6,8 МБ, модель ParkTrack OpenVINO около 19 МБ. Основной расход создают PostgreSQL и снимки MinIO.

Один цикл сохраняет исходное и размеченное изображения, а также небольшой файл меток. Если пара изображений занимает около 1–2 МБ, то одна камера создаёт примерно:

- 0,3–0,6 ГБ в сутки при обработке раз в 5 минут;
- 1,4–2,9 ГБ в сутки при обработке раз в минуту.

Поэтому даже для демонстрации нужно настроить срок хранения. Практичный вариант: хранить все снимки 7 дней, затем оставлять только события или один контрольный снимок за больший интервал.

## 6. Что измерить перед арендой сервера

На тестовом компьютере нужно записать:

1. время обработки одного цикла для одной камеры;
2. максимальное потребление RAM контейнером детектора;
3. среднюю загрузку CPU;
4. объём снимков за сутки;
5. скорость роста базы;
6. поведение при одновременной работе 2, 4 и 8 камер.

После этого сервер выбирается с запасом около 30 процентов по CPU и памяти.

## 7. Настройки безопасного серверного запуска

- наружу публиковать только веб-интерфейс и API через reverse proxy;
- не открывать PostgreSQL и MinIO в интернет;
- использовать HTTPS;
- заменить все демонстрационные пароли и токены;
- ограничить размер журналов Docker;
- выполнять резервную копию PostgreSQL;
- установить лимит и срок хранения объектов MinIO;
- включить автоматический перезапуск и health-check контейнеров.
